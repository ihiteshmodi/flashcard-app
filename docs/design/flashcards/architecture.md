# Architecture

Broad strokes, approved by the owner. Personal, offline, one phone, no accounts.

## Choices
| Decision | Choice | Why |
|---|---|---|
| Platform | iOS 17+, SwiftUI | Native feel, gesture-driven swipe |
| Storage | One SQLite file via the system `SQLite3` library | Offline, the file itself is the backup; no third-party dependency |
| Layout | Swift package `FlashcardsCore` (`src/`) + thin app target (`app/`) | Rules testable with `swift test`, no simulator |
| Project file | Generated by XcodeGen from `project.yml`; not committed | Fresh clones rebuild it |
| Card content | Private seed JSON built by `tools/build-seed` from the source export; not committed | Content stays out of git; stable card ids survive text fixes |

## Layers (inside a feature)
```
SwiftUI view  ->  @Observable presenter / service (Flashcards facade)  ->  SQLite (Database)
                       |
                  rules and queries (no UI imports, no Date(), no randomness)
```
- `Roles` injects the clock, shuffle and id generation. Tests pass fixed ones.
- The database is real everywhere; tests use `:memory:`. No hand-written fakes are needed, so there are no fakes without contract tests.
- `Flashcards` (in `src/`) is the application interface. The app's composition root (`app/`) is the only place that picks file paths, launch arguments and the live roles.

## Domain notes
- People and groups are both rows in `profile` (`kind`), tracked fully separately. A group only lists member people and labels who answered.
- A card's state per profile is `asked` or `skipped` (no row = unseen). The stack is unseen cards (shuffled) then skipped ones; asked cards never return until Start Over.
- Undo and Redo live in the in-memory `CardSession`; undo restores the previous state and never deletes the saved answer.
- Dates are stored as seconds since 1970 (`REAL`). Schema version in `PRAGMA user_version`, upgraded by a migration ladder (`Migrator`).
- Backup: export uses `VACUUM INTO` (consistent copy). Import validates the file, keeps a safety copy, then restores in place with the SQLite backup API and migrates.

## Folder layout
```
src/modules/<capability>/<feature>/   rules and services per feature
src/shared/                           Database, Migrator, Roles
app/                                  SwiftUI screens, composition root, demo data
tests/<capability>/<feature>/         .feature file + XCTest specs (mirrors src)
tests/ui/                             XCUITest high-value flows
tools/build-seed/                     importer from the source export (with its own tests)
docs/design/flashcards/               impact map, architecture, test strategy
```
